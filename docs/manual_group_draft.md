# 完整原文进入群草稿

当前阶段由 Luna 执行桌面操作，人工最后按发送。这个阶段可继续调整；草稿适配器始终只负责草稿，自动发送需使用另一个明确的交付入口。

`helpdesk.manual_group_draft.ManualGroupDraft` 从本机保存的真实 DeepSeek 原文包读取答案，核验完整原文及原生 Clipboard 证据。执行器在当前企业微信原群建立短期 pin，绑定包编号、原群观察名称、原学生观察名称、原文哈希、复制记录、窗口及群头/头像区域。pin 最长五分钟，输入位置须在已观察的编辑区内；它不宣称获得平台永久群ID。

程序核验原群和空编辑框，用 Clipboard 粘贴完整原文，读回后逐字比对，并停止在群草稿。它不调用 Type、Enter、发送按钮、Workflow.dispatch，不新建已发送或绩效记录。每次鼠标/键盘动作带原生 WXWork 前台检查，群头和窗口变化立即停止。正文保留原有换行，不压缩、不改写、不加测试前缀。

每个原文包只记录一次草稿尝试。超时、目标变化或读回不符保留不确定结果，后续调用不重复粘贴；旧的成功记录也不证明当前编辑框仍有草稿。

Luna 恢复桌面执行并观察最新原群后，可调用：

```powershell
python tools/stage_group_answer.py --packet-root data/private/answer-review-packets --packet q34-20260930 --pin <本次执行器生成的本地群pin.json>
```

`--check-only` 只验证保存原文和pin，不操作桌面，也不证明当前群已通过现场核验。当前真实第34题尚未由这个适配器放入群草稿，后台测试不替代现场验证。

对于新题，题面首次审核及冻结事务完成、Luna 执行 FAST Skill→题目上传后，准备命令可带 `--operator-task <task_id>`。候选固定保存到该任务的 `preparation-candidate.json`，自动复用原审核生成准备契约，不要求再填写审核。工作台生成入口同样会承接任务已有的 FAST 候选。这解决第二次审核要求；新建真实网页聊天和首次审核后的自动排队仍需单独接通，不能据此声称完整编排已完成。
