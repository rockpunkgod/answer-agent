# 企业微信英语答疑与绩效统计

个人自用的 Windows 本机工作台：保存消息原文和附件、核对学生题面、查看 DeepSeek 网页生成的讲解，并按天导出绩效草稿。核心使用 Python 标准库、SQLite 和本地文件，不要求部署 Worker 集群、消息中间件或额外数据库。

**当前工作台可运行，支持人工实际交付与绩效回流；收到和答案任务已分离，接入可配置自动发送与有界重试（匿名/Mock验证）。真实群持续监听、网页队列回调及本批群发送尚未通过真实验收。历史单题操作不代表完整自动答疑上线。**

## 启动

需要 Windows 和 Python 3.11+。在仓库目录打开 PowerShell：

```powershell
.\run_current_demo.ps1
```

打开 <http://127.0.0.1:8767/>。没有采集配置时仍可查看本地台账和日报，页面明确显示未连接，不会自动使用模拟题。已有同模式服务会直接复用，不重复启动或自动恢复暂停的采集。

运行中的旧服务不会因更新代码自动升级。本批未替换本机8767服务；仅查看新工作台可使用 `-Port 8768 -NoAutoCollect`。要继续使用原数据库，先正常停止旧服务，再从新代码启动并指定原数据库及配置；不要让两个服务同时处理同一数据库。

只打开工作台，暂不启动原文导入：

```powershell
.\run_current_demo.ps1 -NoAutoCollect
```

原生文字导入的配置示例是 [config/collector.windows-native.example.toml](config/collector.windows-native.example.toml)。按本机实际目录、身份与阶段填写后，保存为 `data/private/windows-native-demo/collector.local.toml`，或通过 `-CollectorConfig` 指定配置。这个适配器导入已保存的 Windows-MCP 原文，**不会自行监听客户端、推断学生时间或发送“收到”**。

GUI观察适配器要求提供者给出群内可持续定位的消息位置，不能使用屏幕坐标或当前可见行号。重启及重叠观察复用消息身份，保留首次原文和证据；内容、发送人、原始时间或归属变化仍停下核对。位置缺失的记录保留为未核验材料，不自动应答。此适配器尚未接入真实持续观察提供者，不把文件导入或匿名测试当作实时收题。

原消息题面入口使用配置中的 `[stage] source_review_manifest` 指向审核通过的本地教学包。新的教学来源仅使用 [ANSWER](https://github.com/rockpunkgod/ANSWER.git)；仓库不包含私人课程材料、登录状态或模型密钥。实际网页、模型或 Windows-MCP 操作才需要相应工具和登录，不是打开台账的依赖。

Windows-MCP 已装在其他工作目录时，可在启动本项目的 PowerShell 中指定现有环境，不需要复制或重新安装：

```powershell
$env:HELPDESK_WINDOWS_MCP_HOME = 'E:\作业帮\.venv-windows-mcp'
```

网页准备、生成、受控交付和现有Worker入口统一使用这个目录中的 `Scripts/python.exe` 和 `Scripts/windows-mcp.exe`，执行的仍是**当前业务检出目录**的封装与保护逻辑。配置只对当前进程及其子进程生效，不修改系统设置；未配置时沿用仓库内 `.venv-windows-mcp/`。只接受本机绝对目录，不接受命令、网址或网络共享。工具缺失会停止，不自动安装或改用其他自动化。该配置本身不证明群聊持续采集已经接通。

Luna定位工具`suggest(..., display_index=...)`可选择当前获准的一块显示器，默认仍为1。位置按本次截图的实际区域和图像比例换算，支持负坐标、主屏及布局变化；显示器编号不等于Windows设备名末尾的数字。返回的是定位建议，调用方仍须用新快照和原生窗口信息核验后才能操作。当前本人已授权所有现有屏幕的只读联调；此授权不自动启用群发送或DeepSeek提交。

现有MCP连接中的`ActivateWeComOnDisplayByApp`接受已核对的`display_index`与`display_device`，先检查该屏幕的唯一企业微信原生窗口及缓存中的同一窗口，再切换一次并复核结果；目标应用不能由请求改写。旧屏幕2入口保持兼容。屏幕0/DISPLAY1上的真实激活与快速Screenshot定位已验证；群内容的Snapshot读取失败，可见画面未提供每条消息的原始时间。截图仅用于定位，不作为消息导出或绩效计数输入。

## 收到与答案独立发送

`AckTask`直接消费原消息的ACK Outbox，不等待OCR、题面审核或DeepSeek；`AnswerTask`消费原有答案/更正Outbox。二者复用同一发送台账和已有阶段策略，没有新增数据库或迁移。后台每秒调度一条到期任务，收到优先；生成等待不会占用该发送循环，UI操作期间不持有业务数据库写锁。审核是否必需仍由`stage.answer_review_required`控制：需要审核时批准后自动发，不需要时按原题面确认流程继续。MANUAL/DISABLED目的保持原义，开启发送循环不会改成AUTO。

默认入口保持现有Worker边界，不启用真实自动发送。选用本机自动入口时，先正常停止同端口旧服务，将[发送配置示例](config/automatic-delivery.example.json)复制到忽略的`data/private/automatic-delivery.local.json`。示例是禁用状态，控件名是占位符。必须实际核验显示器范围、唯一群标题及其标题栏容器、编辑器和本人消息容器，保存证据并填写reviewer，再启用`enabled/allow_real_send/controls_verified`；不能仅改布尔值冒充验证。`group_key/student_keys`使用原消息的已核验绑定，禁止用LLM指定目标。显示器索引可配置，本机仅授权屏幕2（`display_index=1`）；所有点位来自当次快照，支持负坐标。

采集配置仍需实际可读取的原消息库、可靠身份与原始发送时间。新发送入口没有补齐持续收题生产者；文件导入仍是文件导入。ACK的实际来源每次重新核验，练习/模拟记录不会被自动提升为正式外发。答案还需原有SOURCE_MESSAGE任务、有效题目/上下文/ANSWER教学证据。ANSWER缺项仅阻止受影响的教学分支，不是收到任务的启动依赖。

在本机采集配置`[stage.delivery]`中按授权设置`ACK="AUTO"`、`ANSWER="AUTO"`、`CORRECTION="AUTO"`；其他目的不自动放开。保留已有`answer_review_required`选择及`require_ack_before_generation`。启动：

```powershell
.\run_current_demo.ps1 -AutomaticDeliveryConfig 'data/private/automatic-delivery.local.json'
```

这个显式选项使用现有Windows-MCP本机发送入口，不同时启用Worker桌面发送；仍使用同一数据库和原Outbox。进入工作台“收到与答案发送”：查看学生、群、原文稿和重试时间；按阶段需要核对批准；暂停/恢复；对`SEND_UNKNOWN`使用“只读核验发送结果”。`GET /api/delivery/tasks`提供分别的收到/答案状态，`POST /api/delivery/control`只接受既有任务的pause/resume/approve/inspect，需要原有本机Origin和CSRF令牌，不能提交目标或路径。

仅窗口暂不可用、明确临时预检失败或桌面锁忙可自动重试，默认最多3次，间隔5/10秒；次数与到期时间写入现有审计表，重启保留。群/窗口歧义、验证码、旧版本、输入草稿残留、未知超时不盲目重发。发送键只按一次，以新出现的本人消息和完整剪贴板原文核验；旧“收到”、学生同文或旧剪贴板不算新回执。中断的SENDING转SEND_UNKNOWN；未结束的MCP调用会暂停，并阻止另开连接。暂停不能撤销已在执行的输入，需核验其结果。

本批自动交付仅支持已核验、当前前台目标群的文字，不自动切群或选择其他窗口。确认送达后回流原任务和已有绩效归并；ACK、草稿、未知发送及模拟发送不计已完成绩效。缺语义关系或交付证据时继续待核对，图片/语音和多部分交付沿用原人工登记。运行中的8767旧服务、正式数据和发送开关未由本批修改；真实新消息收题、群发送与网页生成尚待单独验证。

## 教学来源与只读预览

[config/teaching-source.toml](config/teaching-source.toml) 固定 ANSWER 提交 `57159d7a8b03a0743225ed27f3f1e6128bbcd45d`。不自动拉取、切换提交或改写教学文件。教学目录存在未提交改动时停止，保留原文件供本人审核；Windows 的 LF/CRLF 换行差异允许核对，预览使用 Git 提交的原始字节。

本机已有该版本的 ANSWER 检出目录，可在业务仓库中运行：

```powershell
python -X utf8 -B -m tools.prepare_teaching_bundle --question-type 阅读理解 --repository "E:\作业帮\.tools\ANSWER-reference"
```

这是**本地原文预览**。工具按 ANSWER 的 README 分工选取当前题型完整文件，合成一个教学输入文件，并保存源文件、提交和哈希；同版本同题型复用缓存。语法使用旧版语法 Skill，写作使用 `gaokao-writing`，不混用主 Skill 内的同名题型文件。结果留在忽略的 `data/private/teaching-bundles/`。

当前 ANSWER 客观题目录缺少 README 和 Agent 定义要求的 `gaokao-english/scripts/check_lesson.py`，预览会明确报告缺项；不借用语法目录的脚本。语法检查脚本虽然存在，本轮未执行课程定位与修稿流程。新预览包均保持 `answer_generation_allowed_by_course=false`，不能通过修改清单把它提升为已验证生成权限。

新代码在生成、上传和中断后再次提交前检查 ANSWER 来源及冻结内容。旧本机教学包不能继续用于这些操作；旧消息、生成稿和交付记录仍可查看、核验。缺少来源绑定的旧任务需要重新核对并冻结输入，不能修改 JSON 冒充通过。

有效的 ANSWER 预览包可以配置为 `source_review_manifest`，打开题面核对和人工工作台；页面显示缺项或尚未启用的原因，不启动自动生成队列。人工答疑后可登记实际交付并核对日报。客观题必需依赖缺失及课程流程未验证仍分别阻止自动生成；业务提示词不再自带英语教学判据，教学方法和讲解方式取自 ANSWER 对应原文。

本轮没有迁移运行中的 `source_review_manifest`、启用新消息渠道或上传教学文件。旧包保留原有历史记录，不作为本次 ANSWER 固定版本验收的证据；新的教学生成需先完成对应课程检查与受控样例验证。停止使用预览命令即可保留当前运行配置；不要用清空数据或覆盖教学文件回退。

## 本人发送给DeepSeek的prompt

本人已确认范围为**所有置顶会话**。只提取实际发出的USER原文和可明确归属的图片标记，DeepSeek回答和业务代码模板不作为样本。原文、会话链接与界面证据只保存在本机私有索引`pinned-user-prompts-20261002.json`，不提交Git，不改教学Skills。

已有真实样本支持三种简短用法：

- 直接提出学生的问题，保留原句、题号及具体疑问。
- 简短点明题号，同时提供对应图片。
- 同题追问继续用简短原句，保留所问的具体细节。

本人另明确要求支持直接发图片；本轮未核验到纯图片、无文字的USER消息，不将角色不清的缩略图当作证据。这些用法仅供LLM参考，不补长篇流程或输出格式要求，也不等于修改ANSWER教学规则或训练模型。

本轮Luna获准只读当前唯一屏幕，核验了真正的DeepSeek窗口及侧栏“置顶”到“今天”的分组边界，逐项核对10个置顶来源：4个取得文字原文（其中2条旁有图片），4个仅见上传文档，1个未取得明确USER消息，1个附件归属待核验。文档附件不算学生题图，也不从AI回答反推输入。样本不是这些会话的完整历史导出。前台切至微信后已停止桌面操作、关闭连接，只离线复核已有证据；未完成的2项回访如实保留。这个只读授权不改变真实群发送配置，样本不作为实际交付或绩效证据。

## 原题候选与人工确认

原题核对是可选的内部入口，默认关闭，不增加发送权限。沿用现有 `Question`、`reference_candidates` 和审计表，**本次没有数据库迁移**。`domain.compare()` 是唯一比较规则：缺少材料、题干、四个选项或必要图表时为 `INCOMPLETE`；题号调整和无歧义选项换序可以对应，NOT/EXCEPT、数字或条件变化不能被文字相似度覆盖。相同数字交换角色或范围端点，也明确标为关键条件冲突。检索报告使用新版本缓存重新计算，已有候选不重复创建；未确认候选刷新差异时保留旧结论，已确认结论变化时停止并要求人工核对。当前精确映射支持四选项客观题，其他题型继续人工核对。

无需联网或业务数据库的匿名演示：

```powershell
python -X utf8 -B -m tools.lookup_reference --demo
python -X utf8 -B -m tools.crawl_reference --self-test
```

演示只使用自建网页样例，报告中的“一致”表示候选逐字段对应，不表示已确认或已使用真实网站。实际任务使用当前题目 ID、版本和上下文版本，查询失败、访问受限和超时分别记录，不显示成“找不到原题”。完整学生题面仍能独立答疑。

启用前将 [配置示例](config/reference-lookup.example.toml) 复制到忽略的 `data/private/reference-lookup.local.toml`，设置 `enabled=true`、保留 `shadow=true`。在没有同端口旧服务时启动：

```powershell
.\run_current_demo.ps1 -ReferenceLookupConfig .\data\private\reference-lookup.local.toml
```

已有服务不会被此参数自动重启；另选端口或先正常停止自己启动的服务。工作台“原题检索与版本核对”选择已有题目、检索原因及必要候选网址，查看学生版与参考版、来源、时间、哈希、差异及选项映射，填写实际核对人和依据后确认或拒绝。界面不显示内部置信度或调试日志。

候选卡的“查看原始识别文本与消息出处”展示保存的原始材料、题干、选项出处、原始发送时间与采集时间。原始识别或录入文本仍是观察证据，不会补成已核验题面。已绑定且校验通过的当前版本原图，可以通过现有本机题面预览入口查看；图片变更、来源失效或尚无绑定时明确显示不能可靠预览，不向浏览器提供本机文件路径。原图预览仍受现有题面入口开关约束。

兼容的 `apply` 接口同样必须提供实际核对人 `reviewer` 和具体依据 `reason`，缺失、空白或格式无效时停止确认；不再自动填写“人工核对”理由。重复确认保留第一次的核对人、时间和依据，不重复增加确认事件、答案或绩效。

候选状态为 `DISCOVERED → COMPARING → MATCHED_CANDIDATE → CONFIRMED / REJECTED`，明确不一致也会被规则直接拒绝。不完整题面不进入确认。**Shadow 可以保存人工确认，但不向答疑提供参考。** 经样例验收后显式设置 `shadow=false`，在工作台确认候选或点击“用于答疑”，才允许符合来源保存许可的参考进入当前题目的冻结输入。学生原题、首次提问时间、实际交付和绩效不因此改变。

确认后的来源、题面、版本、比较结果和依据随同题面文本准备到 DeepSeek；带原图时也准备这份文本。外部答案和解析不用于证明同题，也不进入教学输入。ANSWER 仍是唯一教学来源，学生选项字母优先。更正待核对、内容改变、版本过期或候选被拒绝时，相关旧输入和答案在上传、批准或发送前停止。普通追问继续使用同一题目版本；重复检索、确认和重启不重复建候选。

抓取入口复用 `LocalProvider`（本人放入获准目录的 UTF-8 文件）和 `HttpProvider`（准入、robots、公开地址、固定连接地址和完整超时检查）。`crawl_reference` 不再启动原有未经同等防护验证的浏览器路径；Crawl4AI 浏览器适配暂缓，不要求安装它。提供已有任务信息时，此工具仅建立候选并比较：

```powershell
python -X utf8 -B -m tools.crawl_reference --config .\data\private\reference-lookup.local.toml --local-file demo.html --db .\data\native-demo.db --question-id <已有题目ID> --question-version <当前版本ID> --context-revision <当前上下文版本>
```

本地文件必须位于配置的 `fixture_root`，不是任意文件路径；不要将私人聊天记录放入参考目录。真实网址还需 `network_enabled=true` 及该来源单独批准。Brave 搜索密钥仅从配置指定的环境变量读取，不写入配置或日志；本轮未调用付费搜索。七个列出的题库来源默认未批准自动抓取，完整能力与准入状态见 [当前进度](docs/STATUS.md)。

临时第三方正文只保留在有限时长的内存中；来源明确允许保存业务参考时，必要候选题面才写入现有本机表。关闭 `enabled` 可以停止新增核对，不删除记录；已经用于答疑的参考需先在工作台拒绝以撤销使用，然后关闭开关。不要回退到会自动信任旧参考记录的程序版本；历史未确认记录需要重新比较，不静默升级。

## 日常使用

1. 启动后检查采集状态，先保存原消息、原始发送时间及图片。缺少可靠身份或原时间时补充证据。
2. 在“学生题面确认”核对题面是否清楚。确认后进入同一持久队列；网页执行者未连接时显示等待，不伪造生成。已有 DeepSeek 讲解可以展开和复制完整原文。
3. 按当前阶段配置审核与交付，人工发出后在“登记实际交付”保存实际内容、时间和依据。阶段支持自动“收到”及人工最后发送答案，但真实自动闭环仍待接通。发送前检查任务绑定的群、学生和有效版本；结果不确定时暂停核验，不自动重发。历史题练习保持禁发。
4. 按日期查看统计草稿或下载日报。输出白天综合、语法听力、夜间答题三项数量，以及明细和待核对记录；覆盖不足时明确区分本地小计和未知的正式总数。

工作台“登记实际交付”支持两种现有任务：已有正式生成稿，以及已归属、已核对题目版本但由老师直接回复的学生任务。选择原任务，填写**实际发出的内容、实际时间（含时区）、核验人和依据**，勾选已实际交付后保存。这里不粘贴或发送消息，不伪造平台消息ID、自动回执或学生已读。原生成稿保留，追问使用实际交付历史。

已准备的 DeepSeek 网页任务会把本轮原话及实际交付历史加入冻结上下文附件，保留回复原文、时间、当时题目版本与各部分。普通追问聚焦本轮疑点；更正或异议重新核验当前学生版本。未发送稿、“收到”和发送不确定不能充当上一轮实际回复；历史附件只提供登记的名称与摘要，不自动上传文件或猜测内容。准备、提交、输出保存及审核前检查上下文变化，变化后旧稿停止使用。

上下文文本缓存使用独立的 `question-context-v1` 文件名，不覆盖旧材料。旧准备包缺本轮上下文或内容发生变化时暂停并重新准备，不静默升级、不重新提交已尝试的生成。这个改动接在现有网页适配器内；默认工作台的真实网页执行回调仍未连接，不代表已开启自动答疑。

真实 Windows-MCP 网页准备的本地 `controls` 配置必须包含 `display_index`，编号先按 `DisplayInventory` 核对。本机屏幕 2 当前对应 `"display_index": 1`；不要将这个编号或显示器位置当成其他环境的固定值。上传、原文核验与生成沿用同一个显示器配置，每次读取新快照的范围与当前控件坐标，支持显示器在主屏上方或左侧的负坐标。范围、页面身份或操作位置无法确认时停止。旧的无显示器配置准备证据仍可离线复查，不能直接用于真实桌面执行。

运行网页准备或生成前，由本人或已授权的 Luna 把本任务认领的 DeepSeek 会话放到前台。执行入口不再根据旧窗口标题自动切换浏览器；当前页面必须重新核验为该会话。这些检查不代表工作台已接通真实自动收题或网页执行。

如果该任务的原消息库已保存可核验的单条老师文字回复，可在“实际交付来源”中选择它。系统只列出同一来源、同一群、配置中已声明的老师或本人身份，检查原始时间、引用与采集冲突；有引用时必须对应本次原提问，没有引用时由本人核对归属。内容与时间从原记录读取，再填写核验人和依据、确认后保存。同一原回复不能重复登记为不同交付部分。

这个入口仅读取已保存记录，不是持续监听或自动交付观察。最近100条符合来源范围的老师记录中，最多展示20条可核验的纯文字选项；来源未配置、不可读或没有可选项都不等于群里没有消息。当前整段聊天原文导入常缺可靠的单条发送人或时间，不能直接升级成这类选项，仍可手工填写实际交付。图片、语音及其他交付继续使用原有人工内容/附件登记。源记录变化、出现采集冲突或原消息库不可读时，原交付事实保留，已核验完成与正式计量需重新检查，不静默覆盖。

多部分交付先确认总部分数，再分别登记；只登记一部分不算整项完成，也不进入已确认数量。每部分内容不可静默覆盖；重复保存复用原记录。全部核验后取消同轮次尚未发送的旧稿、停止旧生成任务，防止恢复后重复答复。题目已更正时保留历史交付证据，绩效转待核对。暂停或禁发仍允许记录已发生的人工交付，不增加发送权限。

实际交付附件可先放入**业务数据库所在目录的 `delivery-attachments/`**，再从页面选择；仅读取该目录内现有文件，记录实际哈希，不读取任意路径。没有该目录也能登记纯文本。已确认语义关系自动复用原计量单元；缺可靠归属、原始时间或支持口径时保存交付事实并提示绩效核对，不按消息条数补齐。没有原学生任务的老师回复，仍需先归属到正确题目。

人工接管前在工作台停止采集和发送。恢复只解除暂停，不会开启已禁用的发送目的。Ctrl+C 停止自己启动的服务；重启使用同一数据库保留任务与记录。

默认业务数据库是 `data/native-demo.db`，原消息库是 `data/native-messages.db`；有采集配置时沿用其中的数据库。`data/`、附件、浏览器登录状态和本机配置不进入 Git。数据库和重要附件需做可恢复备份；不要通过清空数据库解决异常。

## 业务约束

- 原始发送时间与采集时间分开；重复采集不重复处理。
- 同一学生多题按明确归属关联，学生版本与参考版本分开，选项换序使用学生字母。更正后的过期答案禁止发送。
- 生成、复制、“收到”及发送不确定都不等于实际完成交付。
- 答疑与绩效复用确认后的题目归属，LLM 提出归并建议，程序核验并根据计量台账计算最终数量；追问、补图、纠错不自动增加数量。
- 夜间只看首次独立学生提问的原始时间：23:00（含）至次日07:00（不含），所有适用题型按篇；07:00前归前一业务日。白天语法、听力按小题，白天综合按篇；完成时间和时效独立。单价、零散题归并等未确认规则不自行推断。
- 工具、文件目录及目标受控；验证码、桌面不可用或人工接管时暂停。桌面串行，显示器按当前授权配置；只读联调可使用所有现有屏幕，发送仍需独立核验配置，不重放过期坐标。

规则变更保留在 [绩效规则记录](docs/PERFORMANCE_RULE_HISTORY.md)。可用范围和缺口见 [当前进度](docs/STATUS.md)。
