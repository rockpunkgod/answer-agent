# Answer Agent：英语答疑与每日绩效

个人自用的 Windows 本机项目：一个工作台、SQLite、本地附件和按需启动的浏览器工具。当前结论 **NOT_READY**：个人微信只读采集已接入工作台，但真实持续收题、自动原图获取、ACK、两阶段答疑及实际交付尚未完成整链路验收。

## 当前使用流程

当前个人微信入口：**已确认群 → 历史基线 → 增量采集 → 原消息库 → 工作台查看**。

后续目标：新问题 → 独立“收到” → 题目/版本核验 → 参考题 Top2 → DeepSeek 核验 → 固定 ANSWER 教学 → 原 Outbox/分段交付 → 实际回读 → 每日绩效。个人微信仍是只读原型，不能把采集成功当成后续流程已启用。

| 模块 | 当前处理 |
| --- | --- |
| 采集 | 个人微信使用数据库读取和持续增量轮询，不加载桌面传输或 UIA；现有文件导入继续保留 |
| 原始事实 | 保存来源、群、学生、原文、原始发送时间、采集时间和媒体关系；去重与消息/游标同事务 |
| 图片 | 只读本地已缓存原图，校验绑定、哈希和实际解码；缺原图不猜、不冒充已下载 |
| ACK 与答疑 | 原 AckTask/AnswerTask 分离；个人微信不进入 ACK drain 或正式教学任务 |
| 教学 | 唯一来源 rockpunkgod/ANSWER，两阶段核验后教学；同学生同问题复用会话 |
| 交付 | 原目标绑定、版本、暂停、顺序分段和回读保护保留；部分发送或 UNKNOWN 不算完成 |
| 绩效 | 复用已确认归属与实际交付；日报输出确认数量、明细、待核对记录 |

ANSWER 冻结版本：`1c388a0596b13935ae7c6a1af00834915a8efa33`。不混用旧本机教学 Skills，也不静默更新同一验收批次的内容。

## 启动、停止与恢复

Windows、Python 3.11+。核心工作台不要求额外数据库、消息中间件或独立 Worker 服务。个人微信采集使用已有私有隔离环境，不把上游完整包装入生产依赖。

在仓库目录执行：

```powershell
./run_current_demo.ps1 -Port 8768 -CollectorConfig data/private/replica-runtime/collector.local.toml -NoAutoCollect
```

打开 `http://127.0.0.1:8768/`，点击“启动采集”；“停止采集”保留游标，重新启动继续。去掉 `-NoAutoCollect` 可随工作台启动轮询。**不要同时另开独立 watch**，也不要运行两套服务处理同一库。

本机私有 TOML 已准备；其他环境须按[配置示例](config/collector.personal-wechat.example.toml)关联已审核的 JSON、隔离解释器与同一消息库。首次先完成历史基线：

```powershell
& data/private/replica-runtime/venv/Scripts/python.exe -X utf8 -B tools/personal_wechat_collect.py history --config data/private/replica-runtime/source.local.json
```

只做独立采集时，同一命令的 `poll` 读取一次增量，`watch` 持续轮询；不需要同时打开工作台。默认间隔5秒，实际延迟还包含读取耗时，不宣称5秒 SLA。失败、超时或游标不连续时停止核验，不清库、跳消息或重建游标。

旧服务不会自动升级。如果显式指定的采集配置与运行中服务不同，启动器会拒绝静默复用；换端口或先正常停止旧服务。没有配置时，可用 `./run_current_demo.ps1 -NoAutoCollect` 只打开原工作台。

详细采集命令、数据范围、恢复边界和真实验证见[本地采集说明](docs/PERSONAL_WECHAT_LOCAL_SOURCE.md)。

## 答疑、交付与日报

工作台继续复用现有待处理任务、原题/生成稿、暂停与恢复、未知发送核验、人工实际交付登记和日报导出入口。配置模板仍在 `config/`；未配置或未验证的浏览器与发送入口保持关闭，不因接入采集自动启用。

已确认语义关系的可信原来源，可在原 ego 两阶段配置中显式启用 `admit_confirmed_sources` 自动创建 AnswerTask；它不提供语义分类模型，也不解除个人微信只读门禁。ACK、生成稿和发送不确定均不能计为已完成答疑。

日报三栏：**白天综合、语法听力、夜间答题**。白天语法/听力按题，23:00之后适用题型按篇，依据独立问题的学生原始发送时间；普通追问、补图、OCR纠正、题号调整和选项换序不重复计量。跨午夜、结算及单价沿用已确认配置，未确认内容保留待核对。重复导出不重复入账，提交后的报表修订保留差异。

自动发送仍使用原 Outbox：目标来自原任务；版本或 ANSWER 变化则拦截；某段 UNKNOWN 时停止，不重发已核验段。企业微信当前真实测试仍停止在答疑正文发送之前。
个人微信“测试”群现已另获完整发送测试授权，三个答疑群仍只读。专用测试交付适配器已接入原测试 Outbox，但当前账号/会话核验尚未真实通过，尚未启用自动发送；不能直接运行旧企业微信发送命令代替它。

## 保留与停用

| 处理 | 内容 |
| --- | --- |
| 保留 | 原始事实、去重、持久游标、版本/选项映射、ANSWER 检查、有限重试、实际交付、绩效、密钥与路径保护 |
| 当前默认 | 现有工作台控制采集；独立 CLI 用于历史基线、维护或单独运行 |
| 移出采集入口 | 未成功取原图的 Qt/UIA 实验命令；代码、测试和原失败证据保留，不能作为可用取图流程 |
| 按需兼容 | 已有企业微信原生 CLI/MCP、文件导入、Worker 和旧任务恢复；不为精简重写稳定实现 |
| 不扩建 | 官方 CLI/SDK 新通道、多个调度 Agent、多节点、自动主备、完整题库和大型监控 |

采集入口不再读取前台窗口元数据；不需要 Windows-MCP、UIA、截图或抢占焦点。去手写保持按需单图能力，有道搜题继续停用。完整上游发送、联系人修改及朋友圈功能不导入。
